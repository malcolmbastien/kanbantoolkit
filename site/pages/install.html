Install it

Flowline is free software. It is one Node process, one SQLite file and a directory of static files — the same routes and the same rules as the Cloudflare Worker build, with no service in between and nobody to ask.

What you need

  • Node 26, and a directory you own. The repository has no build service and no binary to trust.
  • A reverse proxy for TLS — Caddy, nginx, Traefik; anything that can terminate HTTPS and forward to a port.
  • A backup: one file, copied somewhere else, on a schedule. The file is the database, and the backups are yours.

The three commands

git clone {{repo}} flowline
cd flowline && npm ci && npm run build
PORT=8787 DB_PATH=./flowline.db STATIC_DIR=./dist npm run server

The build writes the site and the app into dist/, and the first run of the server applies the schema migrations and leaves you a database file. There is no account to create first and no key to paste.

There is no container image or package yet, so the commands above are the whole story: a clone, a build and a process. Point your proxy at the port, keep the process alive with whatever you already use to keep processes alive, and the job is done.

What it reads

Everything is configuration, and everything has a default that works:

  • PORT — the port to listen on. Defaults to 8787.
  • DB_PATH — the SQLite file. Defaults to ./flowline.db.
  • STATIC_DIR — where the built site and app are. Defaults to ./dist.
  • LIVE — set it to 0 to switch the live channel off. The app then polls the same feed, which is what a process with no socket server does anyway.
  • SITE_URL — the canonical address, for links that leave the app.

The sign-in providers are optional, and an instance with none still runs: the board works, and the app says in words that it has no way in configured rather than drawing a button that cannot work. The full reference, including the provider variables, is in the documentation.

The honest limits

  • One instance, one team. A deployment is a workspace; the first account to sign in is its administrator. There is no second workspace to switch to, because there is no service above this one.
  • The file is the database. A single SQLite file, with WAL, which is why the backup is a copy and not an export.
  • You own the upgrades. A release may add a migration; the server applies it at start and stops if it cannot, rather than serving a database the code does not understand.
